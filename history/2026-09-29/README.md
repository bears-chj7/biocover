# 2026-09-29 — 독립 CSV 로그 재생

후속 작업: [표시 범위 확장·드래그 이동·CSV 시각 정정](range-seek-time-correction.md).
최신 화면 구성: [8080 단일 포트와 실시간/로그 재생 탭](unified-tabs.md).

사용자는 기존 화면과 컴포넌트를 유지한 CSV 선택·재생·일시정지·정지·재개,
1~50배속 숫자 입력과 증감을 요청했다. **동작 중인 실시간 서비스에 영향을 주지 않는 것**이 제약이었다.

## 구현과 적용

- `replay/`에 독립 Flask 서버·템플릿·CSS/JS를 추가했다. 기본 수신은 `0.0.0.0:8081`.
- 실시간 UI의 스타일을 별도 사본으로 사용했다. 6개 카드, 한 행당 하나의 측정 계열 그래프,
  최근 120행 로그, 평균·최솟값·최댓값 배치를 유지했다.
- 완료된 `data/web/*.csv` 선택 및 PC·모바일의 CSV 업로드를 제공한다.
  `.partial.csv`는 제외하며 업로드는 디스크에 저장하지 않는다.
- 각 브라우저의 monotonic 시계로 CSV timestamp 간격을 재생한다.
  일시정지 중 시간은 제외하고, 배속 변경 전 경과분은 기존 배속으로 정산한다.
  정지는 처음 위치로 초기화하고, 재개는 일시정지한 위치부터 이어간다.
- 통계는 이미 재생한 행만 누적하며 결측을 제외한다. 미래 행을 미리 표시하지 않는다.
- UTF-8, 필수 열, 시간대, 시간 순서, 숫자, 행 길이를 확인하고 20 MiB/100,000행으로 제한했다.
- `scripts/install_replay.py`로 **사용자 서비스** `biocover-replay.service`를 설치·시작했다.
  부팅 자동 실행·linger 설정은 하지 않았다. sudo 없이 사용할 때만 시작/종료한다.
- 최초 unit 검사에서 WorkingDirectory의 따옴표가 경로로 해석되는 오류를 확인했다.
  절대 경로만으로 실행하도록 불필요한 WorkingDirectory를 제거하고 unit 검증을 통과했다.
- [README](../../README.md) 및 [사용 문서](../../docs/replay.md)에 설치·접속·실행·종료·제한을 기록했다.

## 검증 결과

- Python 테스트 15개 통과: 기존 실시간 회귀 테스트 7개 + 재생 CSV/API 테스트 8개.
  원본 파일 해시 보존, partial/경로 이탈/심볼릭 링크 거부, 업로드 비저장,
  제어 API 분리, 잘못된 CSV, Origin/용량 제한 등을 검사했다.
- JavaScript 재생 시계 테스트 10개 통과. 5초 간격 2시간 분량 1,441행을 50배속으로
  모두 반영하고 통계·로그 범위·그래프 범위가 맞는지 가상 시계로 확인했다.
- Firefox 145 headless에서 실제 완료 CSV 117행으로 파일 선택 → 재생 → 일시정지
  → 배속 변경 → 재개 → 정지 → 처음부터 재생 → 50배속 완료를 검증했다.
  CSV 업로드, 잘못된 배속 거부, 6개 카드·그래프, JS 오류 없음도 확인했다.
- 실제 페이지 HTML을 넣은 390px iframe 뷰포트에서 모바일 미디어 쿼리를 확인했다.
  Firefox 데스크톱 창의 최소 너비 500px를 피하기 위한 테스트 방식이다.
  가로 페이지 넘침이 없고, 6개 그래프가 한 열에 정렬됐다.
  스크린샷은 Git 제외 경로 `build/replay-desktop.png`, `build/replay-mobile.png`에 남겼다.
- localhost와 Jetson 자체 LAN IP `192.168.123.101:8081`에서 HTTP 200을 확인했다.
  서버 로그에는 LAN의 다른 IP에서 페이지·CSV 읽기 HTTP 200도 관찰됐다.
- 실시간 `biocover-web.service`는 작업 전후 모두 active, **MainPID 4926**,
  **시작 시각 2026-09-29 08:19:59 KST**로 동일했다. 재시작·정지 명령을 실행하지 않았다.
- 기존 `web/` 소스·정적 파일·실시간 설치기에는 diff가 없다.
  센서 장치를 열거나 실시간 제어 API를 호출하지 않았다. 방화벽·부팅 설정도 변경하지 않았다.

재생 서버는 켜 둔 상태다. 단일 Jetson의 CPU·메모리는 공유하므로 모든 부하 조건에서
실시간 측정 지연이 없다고 보장한 검증은 아니다. 실험 가스·센서 보정은 이번 작업 범위에 포함되지 않는다.

```bash
# 켜기 — sudo 없음
systemctl --user start biocover-replay.service

# 끄기 — 재생 서버만 종료
systemctl --user stop biocover-replay.service
```
