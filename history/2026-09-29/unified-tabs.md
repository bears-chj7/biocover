# 8080 단일 포트, 실시간 / 로그 재생 탭

사용자는 웹 두 개와 결과의 Git 반영 여부를 확인하고, 실시간·재생을 한 포트의 탭으로
합치도록 요청했다. 웹 코드·테스트·검증 결과·작업 이력은 GitHub에 반영되어 있다.
원시 CSV와 시각 정정 전 백업은 기존 `data/` 제외 정책에 따라 Jetson 로컬에만 보관한다.

## 구현

- 기존 `biocover-web.service`의 **8080** 리스너 하나로 통합했다.
- `/`은 상단 **실시간 / 로그 재생** 탭, `/live`는 실시간 화면,
  `/replay/`는 재생 화면이다. `/replay/api/...`, `/replay/static/...`도 같은 포트다.
- WSGI 경로 분기로 두 앱의 업로드 제한·요청 검사를 유지했다.
  재생 앱에는 데이터 디렉터리만 전달하며 센서 객체나 실시간 엔진은 전달하지 않는다.
- 각 화면을 같은 출처의 프레임으로 유지한다. 탭 전환 시 페이지를 다시 불러오지 않아
  선택한 CSV·재생 위치·속도·표시 범위가 유지된다. 재생 중이면 숨겨진 동안도 재생 시계가 진행한다.
- 프레임 내용의 높이를 반영해 페이지 전체를 스크롤하도록 했으며 헤더 중복을 제거했다.
  모바일 한 열 그래프와 기존 카드·로그·통계를 유지했다.
- 탭은 키보드 방향키/Home/End를 지원한다. `/#replay`로 재생 탭을 바로 열 수 있다.
- 재생 JS는 실행 경로에서 API 접두 경로를 구하므로 `/replay/` 안에서도
  실시간 제어 API로 잘못 요청하지 않는다. 파일 업로드도 재생 앱에서만 처리한다.
- README·두 웹 사용 문서를 하나의 서비스 설치·실행·종료 방식으로 갱신했다.
  과거 `install_replay.py`는 독립 실행 호환용으로만 남겼다.

## 검증

- Python 19개, JS 16개 테스트 통과.
- 통합 HTTP 테스트: 페이지·정적 파일·재생 API, 1 KiB보다 큰 업로드,
  Origin 검사, 진행 중 partial CSV 접근 차단, 재생 요청 후 실시간 상태·CSV 동일성 확인.
- Firefox 실제 브라우저: 탭 왕복 후 파일·시각·속도·범위·통계 유지,
  숨겨진 상태에서 진행 중인 재생의 연속성, 같은 포트 업로드, JS 오류 없음 확인.
- 390px 실제 뷰포트 안의 통합 화면과 내부 재생 화면 모두 가로 넘침 없음.
- 로컬 스크린샷: `build/unified-tabs-desktop.png`, `build/unified-tabs-mobile.png`.
  테스트용 8082 서버와 브라우저는 종료했다.

## 운영 반영

적용 전 실시간 API는 `idle`, count 0, active_file null이었다.
에이전트의 `sudo -n systemctl restart biocover-web.service`는 비밀번호 필요로 실패했다.
통합 코드는 준비됐으며 사용자에게 재시작을 요청했다. 재시작 확인 후 기존 사용자 서비스
`biocover-replay.service`를 중지하고 8081 포트 종료를 확인할 예정이다.

```bash
sudo systemctl restart biocover-web.service
# 통합 화면 확인 후 과거 재생 서비스 종료
systemctl --user stop biocover-replay.service
```
