# GPIO 직결 진단 이후 USB 전환 및 최신 상태

시간은 KST. 사용자 명령 출력과 에이전트의 직접 조회를 구분한다.

## 반복 점검과 원인 분리

1. DS18 풀업 연결 전후로 센서 검색을 반복했지만 정상 28-* ROM은 없었다.
   wire/w1_gpio 및 실제 디바이스 트리를 확인했고, w1_therm 추가 로드 후에도
   검색 실패가 지속됐다. [GPIO OS 감사](gpio-os-audit.md)에 상세 기록.
2. 직접 RESET 진단은 내부 driven_low=true였지만 presence 응답이 없었다.
   이후 정적 출력 검사에서 외부 전압 3.4 → 1.6 → 3.4V를 두 차례 보고받았다.
   두 번째 검사는 센서 DATA 분리를 안내한 비교 검사였으며 분리 자체를
   사용자가 명시적으로 재확인한 것은 아니다.
3. 제조사 자료에서 P7/P15의 TXB0108 경유를 확인했다. 4.7kΩ 풀업에 대한
   LOW 근사치 1.66V가 실측과 부합했다. 일반적인 P7+4.7kΩ 직결 안내를 정정했다.
   센서 고장 또는 OS 재설치 필요로 단정하지 않았다.
4. 사용자는 처음 UNO 우회를 거절하고 Jetson 직접 해결을 요청했다.
   이후 USB 방식의 편의성을 확인하고 UNO 연결 및 두 센서 동작을 확인했다.
   현재 확정 스케치는 **DS18 D2 / DHT22 D3**이며 이전 제안의 핀 순서와 다르다.

## USB 수신의 실패와 해결

| 순서/시각 | 확인 및 조치 | 결과 |
|---|---|---|
| USB 최초 조회 | 1a86:7523 CH340 존재, ttyUSB 없음. CONFIG_USB_SERIAL_CH341 미설정 | 드라이버 부재 확인 |
| 드라이버 준비 | 공식 Linux stable v5.15.148 소스와 NVIDIA 현재 헤더로 외부 ch341 빌드 | 빌드/버전 확인 성공 |
| 21:16:50 | 사용자 임시 드라이버 로드 | ttyUSB0 생성 |
| 21:16:53 | brltty가 USB 설정을 바꾼 직후 ttyUSB0 해제 | 수신 EIO 원인 로그 확보 |
| 사용자 후속 조치 | brltty-udev.service runtime mask, USB 재연결 | USB 수신 가능 |
| 21:19 | UNO 5행 수신 | 첫 DS18 결측, 시작 헤더 혼입/재시작 흔적, 마지막 3행 모두 유효 |
| 21:25 | 사용자 영구 설치 실행 | 백업 후 모듈/udev/서비스 설치, CSV 5행 검증 PASS |
| 21:27 | 에이전트 직접 조회 | enabled/active 및 약 2초 간격 CSV 추가 확인 |
| 이후 재부팅 | 사용자 재부팅 완료 보고 | 새 CSV 파일로 수집 재개 확인 |

설치/복원 경로와 로그는 [USB 수신 문서](../../docs/arduino-usb.md)에 기록했다.
수신기 검증: CSV 헤더, 분할 입력, 잘못된 행, NaN/범위 밖 값, 타임아웃,
CSV 출력 및 포트 해제. 시작 입력 버퍼 flush와 빈 행 무시를 추가 검증했다.
모든 측정값은 보정 정확도 검증과 구분한다.

## 재부팅 이후 현재 확인한 값

재부팅 이후 생성된 파일:
`data/arduino/uno-20260913T123118.333885Z.csv`.
21:35:54.459493의 최신 행을 21:35:54.683907에 조회했다.
따라서 부팅 이후 수집 재개는 확인됐으나 USB 탈착 복구 시험은 별도로 미수행.

| 센서 | 값 | 근거/시각 |
|---|---|---|
| DS18 | 27.31°C | 재부팅 후 최신 CSV, 21:35:54 |
| DHT22 온도 | 27.7°C | 같은 행 |
| DHT22 습도 | 57.0% | 같은 행 |
| MQ-4 #1 CH0 | raw 201, 약 0.648V | ADC 직접 읽기, 21:36:07 |
| MQ-4 #2 CH1 | raw 103, 약 0.332V | 같은 읽기 |
| 토양수분 CH4 | raw 824, 약 2.658V | 같은 읽기 |
| MQ-4 #3/#4, CM1106 | 미연결 | 사용자 확정 연결 현황 |

ADC 전압은 VREF=3.3V 가정이다. MQ-4 ppm, MOE 및 토양수분 %는
보정 전이므로 계산하지 않는다. UNO와 ADC 값은 동시 측정이 아니다.

## 저장 정책 변경과 남은 작업

사용자 지시: **CSV는 명시적으로 저장을 요청할 때만 생성한다. 기본은 화면 출력.**

- 자동 수집 중지 명령 `sudo -n systemctl disable --now biocover-uno.service`는
  비밀번호 필요로 실패했다. 사용자에게 sudo 명령을 안내했지만 실행 결과는 아직 없다.
  마지막 확인 시점에는 수집이 계속되고 있었다. 중지 완료로 기록하지 않는다.
- `show_all_sensors.py` 작성: 자동 저장 해제 옵션, UNO와 ADC CH0/CH1/CH4
  통합 화면 출력. 파일 저장 없음, P7/P15 직접 통신 없음.
  Python 문법 검사를 통과했고 이 파일의 read_adc 함수는 실제 센서에서 검증했다.
  UNO와 ADC를 합친 전체 실행은 자동 수집 중지 후 검증해야 한다.
- `install_arduino_usb.py` 변경: 기본 설치에서는 자동 CSV 서비스를 중지/비활성화.
  명시적인 `--enable-logging` 옵션이 있을 때만 자동 저장 활성화/검증.
  이 소스 수정 자체는 이미 실행 중인 서비스를 중지하지 않는다.
- 저장 간격은 향후 **5초**를 제안했으며 아직 5초 통합 저장 루프를 구현하지 않았다.
  UNO 측정은 약 2초 주기. 새 측정이 항상 다른 숫자를 의미하지는 않는다.
  이전 UNO 값을 재사용할 경우 신선도/결측 판단을 추가해야 한다.
- 기존 CSV는 삭제하지 않았고 data/는 Git에서 제외한다. 원시 CSV를 push하지 않는다.

다음 실행 명령(화면 출력 5회, CSV 자동 실행 해제 포함):

```bash
sudo python3 scripts/show_all_sensors.py --disable-autosave --samples 5
```

## 하드웨어 그림과 핀맵 문서화

사용자 요청으로 GitHub 표시용 SVG 4개와 하드웨어 가이드를 작성했다.
전체 데이터 경로, UNO D2/D3 및 DS18 풀업, Jetson 40핀 사용 현황,
MCP3008 16핀 번호/채널/SPI 대응을 포함한다.
NVIDIA/Arduino/Microchip/Analog Devices/TI 자료를 연결하고
현장 확인값과 권장 전원 예시, 미확인 MQ-4 분압 및 모듈 리비전을 구분했다.
기존 wiring.md의 DHT/DS18 연결 표를 UNO 구성으로 갱신하고
과거 P7/P15 직결 정보는 이력으로 표시했다.

생성기: `docs/diagrams/generate.py` (표준 Python).
4개 SVG를 PNG로 렌더링해 글자, 연결선, 칩 홈 방향과 핀 순서를 시각 점검했다.
문서 작업이며 시스템 설정이나 센서 배선은 변경하지 않았다.
