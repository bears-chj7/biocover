# 센서·저장소 세션

## 초기 환경과 연결 정정

장치가 실제 Jetson Orin Nano Super이고 부팅되어 있음을 확인했습니다. 초기 샌드박스에서는 실제 /dev 노드가 숨겨졌으므로 장치 파일 부재를 하드웨어 미인식으로 단정하지 않았습니다.

최종 사용자 정정은 MQ-4 #1·#2, 토양수분, DHT22, DS18B20 연결 / MQ-4 #3·#4, CM1106 미연결입니다. CH2·CH3의 거의 0 값은 미연결 입력이며 고장 근거가 아닙니다.

## SPI / MCP3008

설정 전 각 채널 10회 모두 0. 사용자 헤더 조회에서 SPI 핀이 unused로 표시되어 Jetson-IO의 spi1 (19,21,23,24,26)을 활성화하고 재부팅했습니다. 활성 DT와 실제 ADC 읽기에서 개선을 확인했습니다.

| 단계 | CH0 MQ-4 #1 | CH1 MQ-4 #2 | CH4 토양수분 |
|---|---|---|---|
| SPI 전 | 0 | 0 | 0 |
| SPI 적용 후 | 181~186 | 115~121 | 820~834 |
| DS18B20 설치·재부팅 후 | 168~173 | 109~114 | 804~809 |

SPI 이후 각 검사는 100kHz·500kHz 각각 10회, 채널당 20회였습니다. 값이 읽힘을 확인한 것이며, 실제 메탄 농도나 토양수분 보정은 검증하지 않았습니다.

## DHT22

P15 = PN.01 = gpiochip0 line 85. 사용자 관리자 조회에서 `tristate=1`, `enable-input=1`, `function=rsvd1`, `pull=1`을 확인했습니다. 드라이버 미점유 표기만으로 실제 GPIO 기능을 판단하지 않았습니다.

기존 SPI 오버레이에 P15의 `function=rsvd1`, `pull=0`, `tristate=0`, `enable-input=1`을 추가했습니다. 외부 10kΩ 풀업을 전제로 하며, 컴파일과 fdtoverlay 시험 병합 후 사용자가 백업·설치했습니다.

- 원본 SPI 백업: `/boot/jetson-io-hdr40-user-custom.dtbo.before-dht22`
- SPI+DHT22 소스: [spi-dht22.dts](../../hardware/overlays/spi-dht22.dts)
- 이후 DS18B20 세션은 이 SPI+DHT22 설정을 통합 오버레이의 기반으로 사용했습니다.

재부팅 후 Python 검사에서 51·63·48 에지가 나타났지만 40비트 전체를 포착하지 못했습니다. 핸들을 유지하는 C 폴링 시도도 부분 수신 또는 무응답이었고, 오픈드레인 값 변경 방식의 최종 C 후보는 8회 모두 무응답이었습니다. 유효 프레임·체크섬을 확보하지 못해 온·습도는 미확인입니다.

`dht22_probe.c`는 실험적 진단 코드이며 검증된 수집기가 아닙니다. 실패 기록도 남겼습니다. P15 설정 반영과 실제 센서 통신 성공을 구분합니다.

전환 지연·IRQ 수신·물리 신호를 더 확인해야 하며 성공한 센서 수집 구현으로 분류하지 않습니다.

동시에 사용자에게 DS18B20 DATA–3.3V의 실제 4.7kΩ 풀업 연결/모듈 내장 여부를 질문했습니다. 답변 전에는 저항 존재를 가정하지 않습니다.

## 사용자 Arduino 정상 동작 보고와 DHT 구현 비교

사용자는 같은 DHT22가 Arduino에서 정상적으로 읽힌다고 보고했습니다. 현재 세션이 Arduino 측정을 직접 수행한 것은 아닙니다.
로컬 project/working_space/Arduino/Documents/Desktop의 대상 파일 검색에서는 사용자 Arduino 스케치가 발견되지 않았습니다.
대신 [Adafruit Arduino DHT 라이브러리 구현](https://raw.githubusercontent.com/adafruit/DHT-sensor-library/master/DHT.cpp)을 확인했습니다. 사용자가 이 라이브러리를 썼다고 단정하지 않습니다.

해당 구현은 DHT22 시작 LOW 약 1100µs, 입력 전환 후 짧은 대기, 인터럽트 억제 구간에서 응답과 40비트 펄스 측정, LOW/HIGH 길이 비교와 체크섬 검증을 수행합니다. AVR에서는 포트 레지스터를 직접 읽습니다.
Jetson 진단의 사용자 공간 ioctl 전환·스케줄링·IRQ 처리와 실행 조건이 다릅니다. Arduino 정상 동작 보고는 Jetson 수신 경로·전원/신호 조건을 우선 검토할 근거이지만 Jetson 배선까지 정상임을 보장하지는 않습니다.

## P15 직접 레지스터 접근 진단 준비

사용자가 연결선은 약 30cm, DATA는 물리 P15라고 확인했습니다. 내장 풀업과 3.3V 배선 유지, 외부 저항 추가/핀 이동 없음.
물리 P15는 PN.01, gpiochip0 offset 85로 같은 핀입니다.

GPIO ioctl 전환 지연을 분리하기 위해 `scripts/dht22_mmio.c`를 준비했습니다. 실제 DT의 gpio 레지스터 base=0x02210000와 [Linux Tegra GPIO 구현](https://raw.githubusercontent.com/torvalds/linux/master/drivers/gpio/gpio-tegra186.c)의 N 포트 bank=2/port=1을 확인하여 PN.01 주소 0x02212220을 계산했습니다.
프로그램은 보드·GPIO 이름·점유·입력 상태를 확인하고 P15만 LOW로 구동한 뒤 입력으로 해제해 폴링합니다. HIGH 강제 구동 없이 측정하고 저장한 P15 제어 레지스터를 복원합니다. P7·SPI·pinmux·부팅 파일은 변경하지 않습니다.

컴파일 `gcc -O2 -Wall -Wextra -Werror` 성공. sudo -n 실행은 암호 요구로 중단됐으므로 실제 MMIO 실행·센서 수신은 아직 미검증입니다. 사용자에게 최대 20초 제한과 실시간 우선순위 실행 명령을 안내합니다.

### MMIO 초기 보호 검사 수정

사용자 실행은 `Unexpected P15 config: 0xd ctl=0x1; no MMIO writes.`로 종료했습니다. 이 실행에서는 GPIO 핸들 요청 후 MMIO 쓰기가 일어나지 않았습니다.
0x0d는 GPIO 활성 + double-edge trigger 종류 비트이며 OUT·debounce·IRQ enable은 꺼져 있습니다. 이전 이벤트 요청이 남긴 비활성 trigger 종류까지 거부한 검사 조건을 수정했습니다.
수정본도 출력·debounce·활성 IRQ 상태는 거부합니다. 진단 중에는 비활성 trigger 비트를 지운 입력 설정을 사용하고 종료 시 원래 cfg를 복원합니다. 보드·GPIO 소유권·입력 검사는 유지합니다.
컴파일 성공, 수정 후 실제 측정은 사용자 재실행 대기입니다.

### P15 초기 LOW 관찰 및 안정화 검사 추가

사용자 재실행 결과: `config=13, idle=0`, 이어서 `P15 idle LOW; stop before request.`.
MMIO 측정 요청은 보내지 않았고 저장된 입력 상태로 정리 후 종료했습니다.
GPIO 입력 요청이 이전 LOW를 해제하며 DHT 응답을 유발했을 가능성을 배제하기 위해, 입력 점유 후 2.1초 기다린 다음 100회 HIGH/LOW 표본을 확인하도록 수정했습니다.
안정적인 HIGH가 아니면 MMIO 쓰기 전에 중단합니다. 컴파일 성공, 실제 안정화 결과는 사용자 재실행 대기입니다.
계속 LOW이면 소프트웨어 폴링 반복보다 P15–DAT·GND·VCC·실제 풀업 전기 상태를 확인해야 합니다. 5V 전원 변경은 하지 않았습니다.

### 안정화 후에도 LOW — 사용자 확인

사용자 실행에서 2.1초 대기 후 `idle_high_samples=0`, `idle_low_samples=100`.
프로그램은 MMIO 쓰기 없이 중단했습니다. [결과](artifacts/dht22-idle-low-user.json).
GPIO 요청에 따른 순간 응답만으로 초기 LOW를 설명하기 어려워졌습니다. 센서 고장으로 단정하지 않으며, 추가 읽기 코드 재시도 전에 모듈 쪽 VCC–GND 전압과 실크 기준 배선을 확인합니다.
현재 전원 변경·추가 저항·DS18 설정 변경은 없습니다.

## 사용자 DHT22 전원 실측과 연결 정정

사용자가 DHT22 VCC는 다른 센서와 Jetson P1 3.3V를 공유한다고 정정했습니다. P17은 초기 계획이며 현 배선은 P1입니다.
이후 모듈 전원 실측값을 3.4V로 보고했습니다. 측정기 오차·측정 지점의 추가 검증은 없으며 이 값만으로 고장이나 정상 통신을 단정하지 않습니다. 실제 3.3V 계열 전원이 모듈에 도달한다는 보고로 기록합니다.
DHT22 점검은 사용자 지시에 따라 보류하고 DS18부터 점검 중입니다.
