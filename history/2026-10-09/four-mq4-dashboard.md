# MQ-4 네 채널 수집·웹 표시·기존 CSV 전환

사용자는 웹서비스의 MQ-4 수집을 두 개에서 네 개로 확장하고,
기존 두 개만 수집한 CSV에 #3/#4 값을 0으로 추가하도록 요청했다.

## 구현

- MCP3008 CH0·CH1·CH2·CH3 → MQ-4 #1·#2·#3·#4. CH4 토양수분 유지.
- 실시간 센서 캐시, 5초 수집, CSV raw/전압, 세션 통계, 과거 기록 API에 #3/#4 추가.
- 실시간·재생 카드/그래프 각 8개, 로그 10열. 큰 화면 카드는 4열, 모바일은 2열.
- 기존 그래프 표시 범위·드래그·워터마크·재생 속도·타임라인 기능 유지.
- #3/#4의 위치가 확정되지 않아 유입/유출 의미를 부여하지 않고 번호로 표시.
- 레거시 업로드도 #3/#4가 없는 경우 0으로 읽는다. 새 CSV의 실제 결측값은 0으로 덮지 않는다.
- `mq34_backfilled=1`로 과거 0 채움을 구분하고 재생 화면에도 표시한다.
  0 채움은 사용자가 요청한 값이며 재생 통계에도 포함된다. 신규 실제 수집은 표시가 0이다.

## 실제 CSV 변경

백업: `data/backups/mq4-zero-fill-20261009T135103.688573Z/`

| 파일 | 행 수 |
|---|---:|
| session-20260913T132148.547989Z.csv | 117 |
| session-20260928T212014.797483Z.csv | 1,951 |
| session-20261009T134145.819651Z.csv | 76 |
| 합계 | 2,144 |

각 행에 `mq3=0`, `mq4=0`, `mq3_v=0`, `mq4_v=0`, `mq34_backfilled=1` 추가.
원본의 모든 열을 문자열 단위로 비교해 값·시각·순서가 보존된 것을 확인했다.
CSV 파일명·수정 시각도 유지했다. 임시 파일을 원자적으로 교체하므로 inode/파일 생성 시각은 보존하지 않는다.
원본 전체와 변경 전후 SHA-256은 백업의 manifest.json에 남겼다.
측정 CSV와 백업은 Git 제외 대상이며 코드·절차·점검 결과를 Git에 기록한다.

작업 시작 시 측정 중이었으나, CSV 변환 직전에는 76행을 저장하고 정지 상태로 바뀌어 있었다.
완료 파일만 변환했으며 진행 중인 `.partial.csv`는 수정하지 않았다.

## 검증

- Python 테스트 25개 통과: 수집→CSV→재생 왕복, 4채널 매핑·통계·과거 조회,
  원본 보존·백업·재실행 안전성·저장 중인 파일 제외·잘린 파일 거부·결측 구분.
- JavaScript 테스트 25개 통과: 기존 그래프·이력·재생 동작과 #3/#4 집계.
- 8082의 센서 없는 테스트 서버와 실제 Firefox에서 실시간·재생 8개 카드/그래프,
  로그 10열, #3/#4 값·통계, 1,951행 과거 파일의 0 및 출처 표시를 확인했다.
- 390px 화면에서 가로 넘침 없음. 스크린샷은 Git 제외 `build/mq4-live.png`,
  `build/mq4-replay.png`, `build/mq4-mobile.png`.
- 변경한 실제 ADC 수집 코드로 23:17:46~48 KST 세 번 조회:
  MQ #1 243~246, #2 347, #3 702~704, #4 508~509 raw. CSV를 새로 만들지 않았다.
- 검증 서버와 Firefox는 종료했다.

## 운영 적용 상태

코드·CSV 변경은 완료했다. 운영 서비스 재시작 명령은
`sudo: a password is required`로 실행되지 않아 사용자에게 아래 명령 실행을 요청했다.
재시작 후 운영 API 검증은 아직 대기 중이다.

```bash
sudo systemctl restart biocover-web.service
```
