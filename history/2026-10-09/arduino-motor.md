# 유출 센서 표기와 UNO 모터 프로토콜

사용자 정정: MQ-4 #3/#4도 유출이다. #1 유입, #2/#3/#4 유출로 실시간·재생 이름과 배선 문서를 갱신했다.
새 UNO 스케치는 DS18 D2, DHT22 D3, SG90 D9이며 센서 CSV 사이에 모터 상태 줄을 출력한다.

## 구현

- `#READY`, `#ANGLE,n`, `#STATUS,ANGLE,n/NONE`, `#ERR,...`를 센서 4열 CSV와 구분.
  기존 CLI의 JSON/CSV 출력에는 상태 줄이 들어가지 않는다.
- 숫자 각도와 줄바꿈(`30\n`)만 전송. 상태 조회는 `STATUS\n`.
- 기존 USB 읽기 스레드가 송신도 담당하며 별도 포트를 중복해서 열지 않는다.
  한 번에 한 명령, 범위 0~180 정수 검사, 대응 `#ANGLE` 응답 확인, 시간 초과/리셋/연결 해제 처리.
- 실제 각도 숫자는 사용자가 전송 버튼을 눌렀을 때만 보낸다.
  재연결 후 이전 명령을 자동 재전송하지 않는다. 첫 센서 행 이후에는 STATUS만 자동 조회한다.
- 측정 시작과 별도로 **아두이노 연결** 버튼 제공. USB 연결만으로 CSV를 만들지 않는다.
  연결 후 측정 시작은 같은 포트를 재사용하고, 측정 정지/서버 종료는 연결을 닫는다.
- 화면 각도는 UNO가 보고한 설정값이다. 실제 위치 피드백이라고 표현하지 않는다.
- 새 CSV에 `motor_angle`, `motor_reported_at`, `motor_status` 추가.
  재생은 저장 각도 표시만 제공하고 모터 제어 API가 없다. 과거 모터 값은 알 수 없으므로 빈 값 유지.
- 제공한 스케치를 저장했으며 실물 UNO에 다시 업로드하지 않았다. 로컬 arduino-cli가 없어 재컴파일하지 않았다.

## 검증

- Python 32개, JavaScript 25개 테스트 통과.
  혼합/분할 시리얼 줄, 0/180 경계, 잘못된 값, 동시 명령 거부,
  확인 응답 일치, 시간 초과·리셋·해제 후 재전송 금지, CSV 왕복, API Origin/범위 검사 포함.
- PTY 가상 시리얼에서 실제 수신 스레드가 센서 CSV와 모터 응답을 함께 처리함을 확인했다.
- 센서 없는 8082 서버와 Firefox에서 모의 UNO 대상으로 입력 변경만으로 송신하지 않는 것,
  전송 버튼의 180/0, 181 거부, 기록 횟수 유지, 유출 #3/#4 이름과 재생 각도 표시를 확인했다.
- 390px 화면에서 가로 넘침 없음. Git 제외 스크린샷 `build/motor-live.png`,
  `build/motor-replay.png`, `build/motor-mobile.png`. 검증 서버와 Firefox 종료 완료.
- 실제 UNO에는 STATUS 조회만 수행했다. 2026-10-09 23:33:32 KST 응답:
  `#STATUS,ANGLE,NONE`, uptime 2750ms, DS18 28.00°C, DHT22 27.90°C, 습도 45.00%.
  `NONE`은 펌웨어의 미설정 상태이며 0도가 아니다. 실제 숫자 각도 명령은 보내지 않았다.

## 후속 CSV 보완

이전 운영 코드가 계속 실행된 동안 추가로 저장된 `session-20261009T141413.449147Z.csv` 122행에도
사용자가 요청한 MQ #3/#4 raw/전압 0 채움을 적용했다. 기존 세 파일은 다시 변경하지 않았다.
백업은 `data/backups/mq4-zero-fill-20261009T143454.349060Z/`.
합계 네 파일 2,266행이며 모터 과거 값을 0으로 만들지는 않았다.

## 운영 적용

작업 당시 운영 서비스 PID 4389는 이전 코드를 실행 중이었다.
재시작을 시도했으나 `sudo: a password is required`로 실패했다.
사용자에게 `sudo systemctl restart biocover-web.service`를 요청했으며 운영 API 검증은 대기 중이다.
사용법: [모터 제어 문서](../../docs/motor-control.md).
