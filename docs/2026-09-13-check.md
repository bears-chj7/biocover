# 2026-09-13 센서 점검 기록

## 환경

- NVIDIA Jetson Orin Nano Engineering Reference Developer Kit Super
- Jetson Linux R36.4.7 / Linux 5.15.148-tegra / aarch64
- 초기 인계 자료에는 부팅 불가로 적혀 있었지만 실제 로컬 점검 시 부팅되어 있었음.
- 샌드박스 내부에서는 /dev가 제한되어 보임. 호스트 장치 접근으로 SPI·GPIO 존재 확인.

## SPI 설정 전후

설정 전 CH0~CH4 각 10회 읽기에서 모두 0. 사용자 Jetson-IO 조회에서 P19·21·23·24가 unused.
사용자가 Jetson-IO에서 spi1을 설정하고 재부팅함.
이후 활성 디바이스 트리에서 P19·21·23·24·26의 function=spi1 확인.
부팅 DEFAULT는 JetsonIO이며 `/boot/jetson-io-hdr40-user-custom.dtbo`를 사용함.

100kHz와 500kHz에서 각 10회씩, 채널당 총 20회 읽은 범위:

| 채널 | ADC 최소~최대 | 전압 범위 (VREF 3.3V 가정) | 해석 |
|---|---|---|---|
| CH0 | 181~186 | 0.584~0.600V | MQ-4 #1 입력 읽힘 |
| CH1 | 115~121 | 0.371~0.390V | MQ-4 #2 입력 읽힘 |
| CH2 | 2~5 | 0.006~0.016V | 미연결, 센서 측정값 아님 |
| CH3 | 0 | 0V | 미연결, 센서 측정값 아님 |
| CH4 | 820~834 | 2.645~2.690V | 토양수분 입력 읽힘 |

SPI 설정으로 전 채널 0 현상은 해소됨. 가스 ppm·수분 % 변환 및 정확도는 검증하지 않음.

## DHT22

SPI 설정 전후 모두 P15 측정 요청 3회에서 초기 HIGH, 응답 에지 0개.
사용자 공간 폴링/방향 전환 지연으로 응답을 놓칠 가능성도 있음.
사용자 관리자 조회:

```text
pin 85 (SOC_GPIO39_PN1): (MUX UNCLAIMED) (GPIO UNCLAIMED)
pull=1
tristate=1
enable-input=1
open-drain=1
io-reset=1
rcv-sel=1
io-hv=1
schmitt=0
pull-down-strength=0
pull-up-strength=0
drive-type=0
gpio-mode=1
function=rsvd1
```

입력은 활성화되어 있으나 패드 출력이 tristate 상태여서 시작 LOW를 구동하지 못하는 원인 후보.
P15에 function=rsvd1, pull=0, tristate=0, enable-input=1을 추가한 오버레이를 준비함.
외부 10kΩ 풀업을 사용하며 기존 SPI 설정은 보존함.
컴파일 및 실제 기본 DTB에 대한 fdtoverlay 테스트 성공. 하드웨어 효과는 **미검증·미적용**.
부팅 파일 백업 명령을 안내했으나, 저장소 초기화 시 백업 파일은 존재하지 않았음.

## DS18B20

연결되어 있음. `/proc/config.gz`: `# CONFIG_W1 is not set`.
`/sys/bus/w1/devices` 없음. 현재 커널용 1-Wire 코어, w1-gpio, w1-therm 지원과 P7 설정 필요.
오버레이만으로는 현재 없는 커널 드라이버 지원을 대체할 수 없음.

## 기타

microSD 루트 파일시스템에서 기존 오류 이력 2건 및 e2fsck 권고 로그 확인.
현재 센서 문제나 과거 부팅 실패와 인과관계는 미확인. 파일시스템 복구는 수행하지 않음.

## 다음 순서

1. 기존 SPI 오버레이 백업.
2. DHT22 오버레이 적용 후 재부팅, P15 설정 및 ADC·DHT22 재검사.
3. 현재 커널과 일치하는 DS18B20 드라이버 빌드·설정 방법 검토.
4. 응답 확인 후 가스·토양수분 보정 및 실험 데이터 수집 방식 정리.
