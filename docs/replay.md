# CSV 로그 재생

저장된 웹 측정 CSV를 기존 대시보드와 같은 카드, 한 행에 한 계열 그래프,
최신순 로그, 평균·최솟값·최댓값으로 확인한다. **실시간과 로그 재생 모두 8080 포트**를 사용한다.

## 설치와 실행

현재 Jetson에 설치된 Python 3와 Flask를 사용한다. 통합 기능에 새 패키지는 필요 없다.
서비스는 기존 `biocover-web.service` 하나다. 이미 설치된 환경은 재설치할 필요 없이,
측정을 종료한 상태에서 새 서버 코드를 반영하도록 한 번 재시작한다.

```bash
# 처음 설치하는 장치에서만
sudo python3 /home/judgejack/working_space/biocover/scripts/install_dashboard.py

# 사용할 때 실행
sudo systemctl start biocover-web.service

# 업데이트 적용 — 측정을 마친 상태에서
sudo systemctl restart biocover-web.service

# 종료 — 진행 중인 측정 CSV도 마무리
sudo systemctl stop biocover-web.service

# 상태 및 오류 확인
systemctl status biocover-web.service --no-pager
journalctl -u biocover-web.service -n 30 --no-pager
```

최초 설치기는 서비스를 중지 상태로 등록하며 부팅 자동 실행은 설정하지 않는다.

| 접속 위치 | 주소 |
|---|---|
| Jetson 자체 | http://127.0.0.1:8080 |
| 같은 네트워크의 PC·모바일 | http://192.168.123.101:8080 |
| 재생 탭 바로 열기 | http://192.168.123.101:8080/#replay |

상단 **실시간 / 로그 재생** 탭으로 전환한다. 탭을 바꿔도 재생 파일·위치·속도·범위는 유지된다.
재생 중 다른 탭으로 전환하면 재생 시계는 계속 진행한다. 실시간 측정도 탭 선택과 무관하게 계속된다.
전체 페이지를 새로고침하면 브라우저의 재생 상태만 초기화되며 실시간 서버의 측정 상태는 유지된다.

과거에 별도 8081 재생 서비스를 실행했다면 통합 적용 후 종료한다.

```bash
systemctl --user stop biocover-replay.service
```

`install_replay.py`는 과거 독립 실행 환경용으로 남겨 두었으며 통합 환경에는 사용하지 않는다.
LAN IP는 변경될 수 있다. 서버는 기본적으로 `0.0.0.0:8080`에서 수신한다.
로그인은 없으며 방화벽·라우터 설정은 이번 통합에서 변경하지 않는다.

## 사용 순서

1. **Jetson에 저장된 CSV**를 고르고 **불러오기**를 누르거나, 아래 저장된 세션을 누른다.
   접속한 PC·모바일 파일은 **이 기기에서 CSV 선택**으로 불러온다.
2. **재생**을 누르면 첫 기록부터 표시한다. 파일 선택만으로 자동 재생하지 않는다.
3. **일시정지**하면 현재 시각·값·로그·통계가 멈춘다. **재개**하면 이어서 재생한다.
4. **정지**하면 처음 위치로 돌아가 값과 통계를 비운다. **처음부터 재생**으로 다시 시작한다.
5. 마지막 행에 도달하면 **재생 완료**로 멈추고 마지막 값·통계를 유지한다.

진행 막대는 드래그하거나 클릭해 원하는 시각으로 이동할 수 있다. 키보드 화살표도 지원한다.
드래그하는 동안 재생 시계를 멈추며, 재생 중이었다면 놓은 위치에서 계속 재생한다.
대기·일시정지·완료 상태에서 이동하면 선택한 위치에서 일시정지한다.
앞뒤로 이동할 때 카드·최근 로그·누적 통계도 선택한 시점까지 다시 계산한다.

속도는 1~50 사이의 정수다. 숫자를 입력한 뒤 Enter를 누르거나 입력칸에서 나오면 적용한다.
입력칸의 위/아래 화살표 및 별도 −/+ 버튼도 사용할 수 있다.
재생·일시정지 중 모두 변경 가능하며, 범위를 벗어난 값은 오류를 표시하고 기존 속도를 유지한다.

원본 timestamp 간격을 그대로 사용한다. 5초 간격 데이터는 1배속에서 5초,
10배속에서 0.5초, 50배속에서 0.1초마다 다음 행에 도달한다.
원본 측정의 일시정지 등 긴 시간 간격도 유지한다. 2시간 구간은 50배속에서 약 2분 24초다.
백그라운드 탭에서는 브라우저가 화면 갱신을 제한할 수 있지만, 돌아오면 경과한 재생 시각까지
모든 행을 반영한다. 일시정지를 누르지 않으면 배속 시계는 계속 진행한다.

파일을 바꾸면 기존 재생을 멈추고 통계를 초기화한다. 파일 읽기 실패 시 이전 기록은
일시정지 상태로 남아 재개할 수 있다. 재생 위치·속도는 탭마다 독립적이며 새로고침하면 초기화된다.
한 번 불러온 기록은 서버 연결이 끊겨도 해당 탭의 메모리에서 재생할 수 있다.

## 화면과 집계

- 카드: 재생 시점까지 도달한 가장 최근 행의 값. 결측은 `—`.
- 평균·최솟값·최댓값: 첫 행부터 현재까지 **재생된 유효값**으로 계산하며 결측을 제외한다.
  미래 행은 미리 반영하지 않는다. 그래프 표시 범위와 무관한 누적 집계다.
- 그래프: 재생 시각 기준 최근 5/10/30분, 1시간, 2시간, 전체.
  전체는 세션 시작부터 현재 재생 시각까지이며 미래 기록은 표시하지 않는다. 각 행에 한 측정값을 표시한다.
  결측 및 8.5초를 초과한 기록 공백은 선으로 연결하지 않는다.
- 로그: 재생한 행 중 최근 120행, 최신순. 화면 밖의 과거 행도 통계에 포함된다.
- 시각: CSV의 시간대를 읽어 브라우저의 현지 시각으로 표시한다.
- MQ-4 및 토양수분: 원본 ADC raw·전압이며 ppm·수분 %로 환산하지 않는다.

## CSV 형식과 제한

기본 목록은 저장소 `data/web/`의 **완료된 `.csv`**다. `.partial.csv`, 심볼릭 링크,
숨김 파일은 목록/읽기 대상에서 제외한다. 진행 중인 측정을 종료하거나 파일을 복구하지 않는다.
과거에 복구를 마친 `*-recovered.csv`는 일반 완료 파일처럼 읽을 수 있다.

UTF-8(BOM 허용), 최대 20 MiB, 최대 100,000행을 지원한다.
필수 열은 `timestamp,ds18,temperature,humidity,mq1,mq2,soil`이다.
`timestamp`는 시간대가 있는 ISO 형식이어야 하며 시간 순서가 역전된 파일은 거부한다.
같은 timestamp가 여러 개면 원본 순서대로 함께 처리한다.

선택 열 `mq1_v,mq2_v,soil_v,uno_age_s,uno_status,adc_status,errors`도 읽는다.
빈칸, NaN, null, 무한대는 결측으로 처리한다. 잘린 행·필수 열 누락·잘못된 숫자는
오류를 표시한다. 초기 UNO의 4열 CSV는 이 웹 측정 CSV 형식과 다르므로 지원하지 않는다.

업로드는 서버 메모리에서만 파싱하고 디스크에 저장하지 않는다. 재생 동작은 브라우저에서
처리하므로 CSV를 추가 저장하지 않으며, 원본을 덮어쓰거나 이름을 바꾸지 않는다.

## 실시간과 재생의 처리 경로

- 하나의 웹서비스와 포트에서 `/live`와 `/replay/` 화면을 제공한다.
- 재생 API와 정적 파일은 `/replay/api/...`, `/replay/static/...` 아래로 분리한다.
- 재생 앱에는 실시간 엔진이나 센서 객체를 전달하지 않는다. USB/SPI/GPIO를 열지 않는다.
- 재생 업로드는 메모리에서 처리하며 실시간 JSON 제어 API와 별도의 입력 제한을 적용한다.
- 탭 전환은 화면 표시만 바꾸며 측정 시작·일시정지·종료 API를 호출하지 않는다.
- 재생 시작/정지는 브라우저의 재생만 제어한다. 통합 **서비스 종료**는 실시간 측정도 마무리한다.
- 브라우저 그래프는 약 10fps, 로그는 120행, 그래프 데이터는 선택한 범위로 한정한다.
