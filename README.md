**현재 진행:** 사용자가 UNO에서 DS18(D2)·DHT22(D3) 동작을 확인했고,
USB 수신으로 전환했다. Jetson의 CH340 드라이버 부재를 확인하여 모듈과

**주제: 엣지 AI(측정 중심) 기반 스마트 바이오커버 메탄 산화 측정**

고등학생 과학전람회 심화 탐구 프로젝트입니다. NVIDIA Jetson Orin Nano Super로 바이오커버 컬럼의 유입·유출 메탄, 온도, 습도, 토양수분을 기록하고 처리군 간 차이를 비교합니다. RF/LSTM 등 AI 학습모델은 사용하지 않으며, 수식 기반 분석과 선택적 CuPy GPU 계산을 계획합니다. 현재 구현 범위는 센서 진단이며, 실험용 CSV 수집·보정·GPU 분석은 아직 구현하지 않았습니다.

메탄의 100년 지구온난화지수(GWP)는 CO2 대비 약 27~30입니다. 출처와 평가 기준에 따라 값이 달라지므로 보고서에는 사용한 기준을 함께 기록합니다. [EPA GWP 설명](https://www.epa.gov/ghgemissions/understanding-global-warming-potentials)

문서 기준일: **2026-09-13**. 사용자 제공 인계 개요를 바탕으로 작성했으며, 계획·가설과 현장 확인 결과를 구분합니다. 가스 공급 방식과 안전성 검토는 아직 완료되지 않았습니다.

## 2. 측정 논리와 핵심 지표

연구 가설은 토양 내 메탄산화 미생물의 활동으로 CH4가 감소하고 CO2가 생성된다는 것입니다. 단순화한 반응은 `CH4 + 2 O2 → CO2 + 2 H2O`입니다.

유입 농도 `Cin`, 유출 농도 `Cout`으로 계산하는 후보 지표:

```text
농도 기반 겉보기 제거율 (%) = (Cin − Cout) / Cin × 100
```

원안에서는 이를 MOE(메탄 산화 효율)라고 부릅니다. 다만 다음 조건을 확인하기 전에는 실제 산화 효율로 확정하지 않습니다.

- Cin·Cout에는 각 MQ-4를 개별 보정한 농도를 사용합니다. ADC 값이나 전압의 비율을 그대로 메탄 제거율로 해석하지 않습니다.
- 상부 외기 유입은 CH4를 희석할 수 있습니다. 유입·유출 유량, 누출, 체류시간, 비정상상태의 가스 저장량 변화까지 검토해야 합니다.
- 정상상태에서 같은 온도·압력 기준으로 환산한 유량 Q와 농도 C를 쓸 경우, 유량 기반 제거율은 `(Qin·Cin − Qout·Cout)/(Qin·Cin) × 100`입니다. 이것도 제거된 메탄이 모두 생물학적으로 산화됐다는 직접 증명은 아닙니다.
- 유입 농도가 0 이하이거나 검출한계 부근이면 결측·품질 경고로 처리합니다. 원안의 `cin <= 0 → 0%` 처리는 사용하지 않습니다.
- 음의 제거율도 원자료에 보존합니다. 원안의 `max(0, …)` 처리는 결과를 편향시킬 수 있어 분석값에 적용하지 않습니다.
- CO2 증가는 보조 지표입니다. 유입 바이오가스의 CO2와 토양 호흡도 기여하므로, 상부 CO2 센서 하나만으로 메탄 산화를 증명하지 않습니다.

위 내용은 원안의 측정 구조에 대한 질량수지 기반 검토입니다. 유량 측정과 외기 혼합을 어떻게 처리할지 실험 시작 전에 결정해야 합니다.

GPU에서는 시계열 롤링 평균·표준편차와 CO2 농도 변화율을 계산할 계획입니다. **dCO2/dt는 농도 변화율이며 그 자체가 플럭스는 아닙니다.** 플럭스에는 챔버 방식에 맞는 체적·면적·유량·온도·압력 정보와 수지가 필요합니다. 현재 상부 통기 구조에 밀폐 챔버 공식을 그대로 적용하지 않습니다.

## 3. 대조 실험 설계

처리 요인은 ‘논/하천 흙 첨가 여부’로 계획합니다.

| 군 | 배지 계획 | 검증할 가설 |
|---|---|---|
| 실험군 | 일반 흙 + 논/하천 흙 20~30% | 일반 흙만 쓴 경우보다 메탄 제거가 커지는가? |
| 대조군 | 일반 흙만 | 같은 조건에서의 기준값은 얼마인가? |
| 선택적 멸균 대조군 | 첨가 흙을 멸균한 배지 | 생물학적 기여를 추가로 구분할 수 있는가? |

20~30%가 질량비인지 부피비인지 정하고 동일하게 적용합니다. 일반 흙에도 미생물이 있을 수 있으므로 ‘균이 거의 없고 유출≈유입’은 확정 사실로 두지 않습니다. 흙을 바꾸면 수분 보유력·공극률·유기물도 함께 바뀔 수 있고, 멸균도 흙의 특성을 바꿀 수 있습니다. 관측 차이를 바로 특정 균의 효과로 단정하지 않습니다.

컬럼 규격, 충전량·밀도, 유입 가스 조성·유량, 온도, 수분, 측정 위치를 최대한 맞추고 독립 반복 컬럼 수와 분석 방법을 사전에 정합니다. 5초 간격의 반복 측정은 독립적인 실험 반복 수를 대신하지 않습니다.

현재 연결된 MQ-4 두 개는 한 컬럼의 유입·유출 측정용입니다. 두 컬럼 동시 비교에는 #3·#4의 배치·연결·개별 보정 또는 검증된 순차 샘플링 방식을 추가로 결정해야 합니다.

## 4. 컬럼·반응기 구성안

투명 아크릴/PVC관, 내경 10~15cm, 높이 60~80cm를 제안합니다. 아래 층 높이 범위의 합과 관의 실제 길이가 맞도록 최종 도면에서 확정합니다.

| 아래→위 | 높이 계획 | 역할·배치 |
|---|---|---|
| 가스 유입실 | 5~10cm | 빈 공간, 가스 주입구, MQ-4 #1 기체 측정 |
| 가스 분배층 | 5cm | 5~15mm 자갈과 상부 부직포, 가스 분산·흙 받침 |
| 산화층 | 40~50cm | 실험군/대조군 배지, 토양 온도·수분 센서 |
| 상부 통기층 | 5~10cm | 헤드스페이스, MQ-4 #2·향후 CM1106·DHT22, 통기·배출 경로 |

측벽과 이음부는 누출 없이 구성하고, 바닥에는 관리되는 가스 주입 경로를 둡니다. 상단에는 뚜껑·통기구·센서구를 계획합니다. 외기 혼합으로 인한 희석과 안전한 배출을 함께 고려해야 합니다. CH4와 O2가 만나는 깊이는 측정 조건에 따라 달라지므로 ‘표면 아래 10~30cm’는 원안의 예상 범위로만 기록합니다.

PVC관을 연결하는 구조에는 부직포만으로 흙 하중을 지지하지 않도록 별도 지지 구조를 검토합니다. 원안의 자갈·부직포 조합도 관경과 하중에 맞는 구조 검증이 필요합니다.

### 가스 공급원: 미확정

원안은 컬럼 밖 음식물 혐기성 소화조에서 생성한 가스를 전달하거나 표준 혼합가스를 사용하는 방안을 제안했습니다. **자가 밀폐 페트병 발생조와 40% CH4 실린더를 확정 운용 절차로 채택하지 않습니다.** 공급 농도·유량·압력·O2 조건과 센서 범위를 전문 담당자와 정해야 합니다.

Winsen MQ-4 문서의 검출 범위는 300~10,000ppm입니다. 원안의 40% CH4는 400,000ppm이므로 센서 범위를 크게 벗어납니다. 제조사·모듈별 실제 사양을 확인해야 합니다. [MQ-4 제조사 문서](https://www.winsen-sensor.com/d/files/mq-4-%28ver1_6%29---manual.pdf)

바이오가스는 CH4뿐 아니라 CO2·수분·H2S 등을 포함할 수 있어 안전과 측정 해석을 모두 복잡하게 만듭니다. 단순 물트랩을 인증된 역화방지기·압력해소 장치·독성가스 제거 장치의 대체품으로 간주하지 않습니다. 용기의 재질 이름만으로 압력 안전성을 판단하지 않습니다. [EPA 혐기성 소화 FAQ](https://www.epa.gov/anaerobic-digestion/frequent-questions-about-anaerobic-digestion)

## 5. 배지와 적응·배양 계획

원안의 접종원 후보는 논·하천·연못 가장자리의 축축한 흙이며, 표층 아래 5~15cm에서 소량 채취하고 당일 사용하는 안입니다. 보호구역·채취 허가·현장 위생 조건을 먼저 확인하고 채취 지점을 복원합니다. 색과 습기만으로 메탄산화균의 양이나 활성을 판정하지 않습니다.

배지 준비의 출발 조건은 4mm 체질, pH 6.5~8.0, 수분 30%, 느슨한 충전입니다. 이는 **최적 조건으로 검증된 값이 아닌 설계 후보**입니다. 수분 30%는 건량 기준 질량수분인지 다른 정의인지 확정해야 하며, 손으로 쥐는 촉감만으로 정량하지 않습니다. 토양수분 센서도 실제 배지에서 기준 측정과 대조해 보정합니다.

컬럼 내 적응·농화배양을 계획하며, 원안은 2~4주 또는 논흙 사용 시 며칠~1주를 예상했습니다. 실제 기간은 미확정이며 날짜만으로 적응 완료를 선언하지 않습니다. 시판 흙이 항상 부적합하다거나 논흙이면 즉시 높은 활성을 보인다는 주장도 검증 대상으로 둡니다. 공급 기간·운영 시간·중단 기준은 안전 검토 후 정합니다.

## 6. 센서·전원·배선

구성은 **센서 5종, 계획 수량 8개(MQ-4 4개 포함), 별도 ADC 1개**입니다. 현재 센서는 5개(MQ-4 2개, DHT22, DS18B20, 토양수분)가 연결되어 있습니다. 원안의 ‘7종’ 표기는 수량·종류 혼동을 정정했습니다.

| 장치 | 정식 종류 | 인터페이스 |
|---|---|---|
| MQ-4 ×4 계획 | SnO2 반도체식(MOS) 메탄·천연가스 센서 | 아날로그 → MCP3008 |
| CM1106 | Cubic NDIR CO2 센서, 세부 모델 확인 필요 | UART |
| DHT22/AM2302 | 디지털 온·습도 센서 | GPIO 단일 데이터선 |
| DS18B20 | 1-Wire 디지털 온도센서, 방수 프로브형 | 1-Wire |
| 정전용량식 토양수분 | 모델 미확인 | 아날로그 → MCP3008 |
| MCP3008 | Microchip 8채널 10비트 ADC | SPI |

Jetson 40핀 헤더에는 이 아날로그 센서들을 직접 읽는 ADC 입력이 없어 MCP3008을 경유합니다. 아래 P 번호는 **물리 핀 번호**입니다.

| 장치 | 전원 | 신호 연결 |
|---|---|---|
| MCP3008 | VDD·VREF → P1 3.3V, AGND·DGND → GND | DIN P19, DOUT P21, CLK P23, CS P24 |
| DHT22 | VCC P1 3.3V 공유(실제 배선), GND 공통 | DATA P15, 10kΩ 풀업 → 3.3V |
| DS18B20 | VDD P1 3.3V, GND 공통 | DATA P7, 4.7kΩ 풀업 → 3.3V |
| CM1106, 미연결 | VIN P2 5V 예정 | 센서 TX → P10, 센서 RX → P8 예정 |
| MQ-4 #1 유입 | P2 5V, GND 공통 | AOUT → CH0 |
| MQ-4 #2 유출 | P2 5V, GND 공통 | AOUT → CH1 |
| MQ-4 #3, 미연결 | 5V 예정 | AOUT → CH2 예정 |
| MQ-4 #4, 미연결 | 5V 예정 | AOUT → CH3 예정 |
| 토양수분 | P1 3.3V, GND 공통 | AOUT → CH4 |

CH5~CH7은 미사용입니다. 토양수분은 원래 CH2에서 CH4로 이동했습니다. DHT22의 현 연결은 P15이며, P11의 UART RTS 기본 기능만으로 모든 GPIO 사용이 불가능하다고 일반화하지 않습니다.

### 전압·전류와 설치 위치

- MCP3008 VDD/VREF는 3.3V입니다. MQ-4의 5V 전원과 ADC 신호 전압을 구분하고, AOUT이 3.3V를 넘으면 적절한 분압·보호가 필요합니다. 현재 분압 유무와 실제 최대 전압은 미확인입니다. [Microchip 데이터시트](https://ww1.microchip.com/downloads/aemDocuments/documents/MSLD/ProductDocuments/DataSheets/MCP3004-MCP3008-Data-Sheet-DS20001295.pdf)
- MQ-4 히터를 포함한 총 전류와 전원 용량을 확인합니다. 4개 확장 시 별도 규격에 맞는 5V 전원을 검토하고 공통 GND를 구성하되 전원 간 역급전을 피하도록 설계합니다.
- MQ-4·CM1106·DHT22는 기체 공간에 배치하며 흙에 묻지 않습니다. DHT22 한 개로 헤드스페이스와 외부 대기를 동시에 독립 측정할 수는 없습니다.
- DS18B20 방수 프로브와 토양수분 감지부를 흙에 넣습니다. ‘정전용량식’이라는 이유만으로 기판·커넥터 전체가 방수인 것은 아니므로 실제 제품의 매설·방수 범위를 확인합니다.
- MQ-4 예열·안정화는 실제 제조사 지침과 기록에 따릅니다. 제조사 표준 시험의 초기 예열 조건과 매 실험의 안정화 시간을 구분합니다.

## 7. 소프트웨어 계획과 현재 실행 방법

현재 진단은 표준 Python, Linux SPI ioctl, 시스템 `libgpiod.so.2`를 사용합니다. 센서 접근 권한이 있는 Jetson 호스트에서 실행합니다.

```bash
python3 scripts/check_sensors.py
```

CH0~CH4를 100kHz·500kHz에서 읽고 P15에 DHT22 측정 요청을 3회 보냅니다. 미연결 CH2·CH3 값은 센서 데이터가 아닙니다. DS18B20·CM1106 읽기는 구현되어 있지 않습니다. 추가 C 진단은 아래 기록을 참고하세요. 다른 수집 프로그램과 장치를 동시에 사용하지 않습니다. DHT22 폴링은 스케줄링과 방향 전환 지연으로 응답을 놓칠 수 있습니다.

### 구현 예정

- 5초 주기 폴링, 시각·컬럼·센서 ID·원시값·보정값·단위·품질 상태를 CSV에 저장.
- 예열·보정 이력, 가스 공급·유량, 환경 변화, 접종·수분 조절 이벤트 기록.
- 터미널 출력과 CPU 기준 계산을 먼저 검증하고, 필요 시 CuPy 롤링 평균·표준편차와 농도 변화율 추가.
- 작은 5초 주기 데이터에서는 GPU 전송 비용이 더 클 수 있으므로 CPU/GPU 결과 일치와 실제 성능을 비교.

원안 라이브러리 후보는 `adafruit-circuitpython-mcp3xxx`, `adafruit-circuitpython-dht`, `pyserial`, `cupy-cuda12x`입니다. **설치·호환성 검증 완료 목록이 아닙니다.** Jetson aarch64, JetPack/CUDA, Blinka·GPIO 백엔드 지원을 확인한 뒤 버전을 정합니다.

### 파싱·계산 구현 요구사항

| 원안 함수 | 저장소에서 적용할 검증 기준 |
|---|---|
| `parse_cm1106(resp)` | 헤더뿐 아니라 모델별 응답 길이·명령·체크섬·상태와 분할 수신 확인. 미연결이므로 실물 검증 전 |
| `mcp_to_voltage(raw, vref=3.3)` | `raw/1023 × vref` 환산, raw 범위·실제 VREF·분압비 기록 |
| `moe(cin, cout)` | 보정된 농도만 사용, 무효 유입은 결측, 음수 보존, 희석·유량 조건 표시 |
| `parse_ds18b20(text)` | `t=`뿐 아니라 CRC `YES`, 읽기 오류·변환 상태·측정 범위 확인 |

인계문에 붙은 ‘핵심 함수 검증 완료’ 표기는 이 로컬 시스템에서 확인되지 않았습니다. 현재 저장소에 해당 실험 수집 함수를 구현·검증한 것으로 간주하지 않습니다.

## 8. 실험 진행 순서

1. 가스 취급 안전 검토와 농도·유량·배출 방식 확정.
2. DHT22·DS18B20 지원 완료, 필요한 센서 추가, 모든 측정 경로 및 전압 확인.
3. MQ-4 개별 보정·동일 가스 교차 비교, 토양수분 보정, 누출·희석·유량 측정 방법 확인.
4. 접종원 채취와 배지 조건 기록, 실험군·대조군 및 반복 수 확정.
5. 컬럼 충전·동일 조건 설정·센서 설치.
6. 승인된 조건에서 가스 공급과 5초 주기 기록. 적응 기간은 관측값으로 판단.
7. 원자료 품질 검사 후 시간별 곡선, 처리군 평균·변동·독립 반복 차이 분석.
8. 농도 감소·CO2 변화·미생물 효과를 구분하고 측정 한계를 보고서에 명시.

‘논흙을 넣으면 며칠 안에 큰 차이가 발생한다’는 결과를 미리 가정하지 않습니다.

## 9. 안전과 운용 전 확인

고등학생 탐구는 지도교사와 가스 취급 전문 담당자의 감독·검토 아래 진행합니다. 현재 문서는 가스 운용 안전 승인이나 완성된 제작 매뉴얼이 아닙니다.

- 메탄은 가연성이며 공기 중 폭발하한은 약 5 vol%입니다. **이 수치를 실험의 허용 농도로 사용하지 않습니다.** [NIOSH 자료](https://www.cdc.gov/niosh/engcontrols/ecd/detail121.html)
- 화기·흡연·스파크를 배제하고, 적절한 환기·배출·누출 감지·공급 차단·압력 관리 방식을 갖춰야 합니다. MQ-4 히터와 Jetson 전자장치는 인증 방폭 장비로 간주하지 않습니다.
- 자체 발생 바이오가스는 H2S 등 추가 위험이 있으므로 악취 유무로 안전을 판단하지 않습니다. [EPA 안전 설명](https://www.epa.gov/anaerobic-digestion/frequent-questions-about-anaerobic-digestion)
- 원안의 ‘점화원만 없으면 폭발 위험이 매우 낮다’, ‘물병 트랩이 역화를 막는다’, ‘악취 85% 이상 제거’는 검증된 안전·성능 보장으로 채택하지 않습니다.
- 용기·관·밸브·조절기는 실제 가스와 압력에 맞는 사양으로 선정합니다. 단순 밀폐 페트병, 일반 물트랩, 흄후드만으로 전체 시스템 안전성이 확보되지는 않습니다.
- 감독 없는 연속 가스 공급은 현재 계획으로 승인되지 않았습니다. 운영·정지·이상 상황 절차를 먼저 정합니다.

## 10. Jetson 설정과 다음 작업

SPI 설정은 적용 완료되었습니다. Jetson-IO의 `spi1 (19,21,23,24,26)`에 대해 이 보드의 MCP3008 CS0 경로는 `/dev/spidev0.0`입니다.

```bash
sudo python3 /opt/nvidia/jetson-io/config-by-pin.py -n 1
```

DHT22는 P15의 `tristate=1`을 원인 후보로 보고 SPI 설정을 유지한 수정 오버레이를 설치했습니다. 원본은 `/boot/jetson-io-hdr40-user-custom.dtbo.before-dht22`에 백업되어 있습니다. 이 백업은 DS18B20 변경 이전 버전이므로 현재 통합 설정을 복원하는 용도로 쓰면 안 됩니다. **재부팅·재검사는 완료됐으며 현재 DHT22 프레임 수신과 DS18B20 버스 인식 문제를 진단 중**입니다. 자세한 적용·복원 절차는 [오버레이 문서](hardware/overlays/README.md)를 따릅니다.

DS18B20은 다른 로컬 세션에서 현재 커널용 외부 모듈을 설치했습니다. 재부팅 후 wire·w1_gpio는 로드됐고 w1_therm.ko도 설치되어 있지만 정상 28-… 장치는 아직 인식되지 않습니다. 00-… ID가 계속 바뀌므로 버스 신호·P7 실제 설정·전원·풀업·배선을 추가 확인해야 합니다. 현재 부팅 오버레이는 SPI·P15·P7을 합친 `/boot/ds18b20-pin7.dtbo`입니다.

별도로 microSD 루트 파일시스템의 기존 오류 이력 2건이 관찰됐습니다. 원인·부팅 문제와의 연관성은 미확인이며 파일시스템 복구는 수행하지 않았습니다.

실험 장치의 변경은 배선표, 날짜별 점검 기록, 설정 소스와 함께 Git commit으로 남깁니다. 원시 실험 데이터 보관 위치·용량·버전 관리 정책은 수집 루프 구현 시 결정합니다.

### 추가 DHT22 진단 (실험적)

```bash
mkdir -p build
gcc -O2 -Wall -Wextra -Werror -o build/dht22_probe scripts/dht22_probe.c
./build/dht22_probe
```

P15에 오픈드레인 측정 요청을 보내 최대 8회 폴링합니다. 완전한 펄스 수·체크섬·범위를 통과한 프레임만 출력하며, 성공 프레임이 없으면 종료 코드 2입니다. **현재 보드에서 유효 프레임 확보에 실패했으므로 검증된 수집기로 사용하지 않습니다.** SPI/P7·부팅 설정은 변경하지 않습니다. 사용자 공간 타이밍 한계를 해결하기 위한 후속 검토용 소스입니다.

GPIO v2 커널 에지 기록 진단 후보도 추가했습니다:

```bash
gcc -O2 -Wall -Wextra -Werror -o build/dht22_events scripts/dht22_events.c
./build/dht22_events
```

이 방식도 현재 5회 모두 유효 프레임 미확보입니다. 이벤트 시간과 GPIO 설정 지연을 조사하기 위한 진단 도구이며, 실제 온·습도 수집기로 검증되지 않았습니다.

추가 원인 분리용 `scripts/dht22_mmio.c`는 이 Orin Nano 보드의 P15 제어 레지스터에 직접 접근하는 관리자 전용 진단입니다. GPIO 점유·보드 식별·입력 상태를 확인하고 실행 후 복원하며, SPI·DS18·pinmux를 수정하지 않습니다. 컴파일만 검증됐고 실제 실행 결과는 아직 대기 중입니다. 일반 수집 프로그램으로 사용하지 않습니다.

### DS18 RESET 응답 검사 (관리자용, 센서 응답 미검출)

```bash
gcc -O2 -Wall -Wextra -Werror -o build/ds18_presence scripts/ds18_presence.c
sudo python3 scripts/check_ds18_presence.py
```

현재 Orin Nano/5.15.148-tegra/P7 전용입니다. P7의 w1-gpio 연결을 잠시 해제하고 초기화 응답만 관찰한 뒤 복구합니다. SPI·P15·부팅 설정은 건드리지 않습니다. 사용자 실행에서 P7 LOW 구동은 확인됐지만 초기화 응답 후보는 3회 모두 미검출, 드라이버 복구는 성공했습니다. 온도·ROM 검증은 미완료입니다. 단독 C 바이너리 실행 대신 복구 처리가 있는 Python 래퍼를 사용합니다.
